# Design: paperless-gpt + Ollama in dev

Date: 2026-10-28
Status: Approved

## Goal

Add AI-powered tag and title suggestions to the existing dev paperless-ngx by
deploying two new dev-only workload apps in the `workloads` namespace of the
k3d dev cluster: `ollama` (local LLM runtime with the qwen2.5:3b model) and
`paperless-gpt` (icereed/paperless-gpt, a lightweight UI/worker that talks to
both paperless and Ollama). Tagging/title suggestions only — no RAG document
Q&A and no OCR vision model.

## Architecture

```
k3d-dev (GitHub Codespace, no GPU)
ns workloads:
  paperless-dev (existing)          ollama-dev (new)
    paperless-ngx API                  chart: otwld/ollama-helm
    NodePort 32080                       PVC 5Gi (models, qwen2.5:3b)
  IngressRoute: /paperless             Service ollama:11434
                                        requests 1 CPU / 3Gi, limits 4 / 4Gi
                                      NodePort 32081 + IngressRoute /paperless-gpt
  paperless-gpt-dev (new)
    chart: in-repo apps/workloads/paperless-gpt/chart (isGitRepo:true)
    env → PAPERLESS_BASE_URL=http://paperless.workloads.svc.cluster.local
          LLM_PROVIDER=ollama, LLM_MODEL=qwen2.5:3b
          OLLAMA_HOST=http://ollama.workloads.svc.cluster.local:11434
    PAPERLESS_API_TOKEN via Doppler (project paperless-gpt, config dev)
    SQLite/config/prompts on emptyDir (loseable)
    NodePort 32081 + IngressRoute /paperless-gpt (strip-prefix,
      gated by dashboard-auth basicAuth)
```

paperless-gpt polls the paperless API for untagged documents, asks
qwen2.5:3b (via Ollama) for tag/title suggestions, and writes them back for
review in its own dashboard. Both apps are generated by the existing dev
workload appset (wave 5); no appset changes.

## Decisions

- **App**: icereed/paperless-gpt v0.31.0 — NOT clusterzx/paperless-ai
  (unmaintained since ~March 2026; paperless-gpt is maintained, lighter, and
  produces better suggestions per community consensus). Also considered and
  rejected: paperless-ngx 3.x native AI — suggestions-only, no auto-tag
  rules, no separate dashboard.
- **Model**: qwen2.5:3b via Ollama, CPU-only (codespace has no GPU). The
  model is pulled at pod startup by the chart's `models.pull` mechanism.
- **Two separate apps** (not one combined chart):
  - `ollama`: community chart `otwld/ollama-helm`, 5Gi PVC for models,
    Service `ollama:11434`, requests 1 CPU/3Gi, limits 4 CPU/4Gi.
  - `paperless-gpt`: tiny in-repo chart at
    `apps/workloads/paperless-gpt/chart`, referenced via `isGitRepo: true` —
    the dev workload appset requires every workload to be a Helm chart.
- **paperless-gpt env**: `PAPERLESS_BASE_URL=http://paperless.workloads.svc.cluster.local`,
  `LLM_PROVIDER=ollama`, `LLM_MODEL=qwen2.5:3b`,
  `OLLAMA_HOST=http://ollama.workloads.svc.cluster.local:11434`,
  `TOKEN_LIMIT=1000`, `SUGGESTION_WORKERS=1`.
- **Credentials**: `PAPERLESS_API_TOKEN` from Doppler (project
  `paperless-gpt`, config `dev`) using the same trio pattern as
  `apps/workloads/paperless/overlays/dev`: SealedSecret bootstrap token →
  SecretStore `doppler-paperless-gpt` → ExternalSecret
  `paperless-gpt-credentials`.
- **State**: SQLite, config and prompts on emptyDir — loseable dev state,
  no Postgres.
- **Exposure** (both paths, deliberately redundant):
  - NodePort 32081 + matching port mapping in `k3d-dev.yaml` +
    `"Paperless GPT App"` in `devcontainer.json` `forwardPorts` (requires a
    k3d cluster recreate).
  - Traefik IngressRoute `PathPrefix /paperless-gpt` with strip-prefix
    middleware, gated by the existing `dashboard-auth` basicAuth middleware —
    paperless-gpt has NO built-in auth and the dev Traefik entrypoint 30480
    is public. Known caveat: sub-path redirect/asset jank; the NodePort path
    is the clean one.
- **RAG/embeddings and OCR vision model** are deliberately out of scope
  (tagging/title suggestions only).
- **Appsets unchanged**: both apps land via the existing dev workload
  appset (wave 5), namespace `workloads`.
- **Sync/ordering**: paperless-gpt does not need Ollama at startup — it
  degrades gracefully until the model is available — so same-wave parallel
  sync of both apps is fine.

| Change | File |

## Rollout order & verification

1. Scaffold both app dirs (create-app.sh) → appset creates `ollama-dev` and
   `paperless-gpt-dev` (wave 5) → both pods Running in ns `workloads`.
2. Verify Ollama: `ollama-dev` pod ready, PVC bound, qwen2.5:3b pull
   completes in logs, `curl http://ollama.workloads.svc.cluster.local:11434/api/tags`
   lists the model.
3. Verify paperless-gpt: ExternalSecret synced (Doppler trio), pod connects
   to paperless API and Ollama, dashboard loads.
4. Create the Doppler bootstrap SealedSecret token in Doppler project
   `paperless-gpt` config `dev`, add `PAPERLESS_API_TOKEN` (token created in
   paperless-ngx), run `scripts/create-secrets.sh dev`.
5. Recreate k3d cluster for the NodePort mapping; verify
   `localhost:32081` (forwarded) serves the paperless-gpt dashboard.
6. Verify Traefik path: `https://…/paperless-gpt/` prompts for basicAuth,
   dashboard loads, tag suggestion on an untagged document returns
   suggestions (accept the sub-path asset jank caveat).
7. End-to-end: upload an untagged document to paperless-ngx → suggestion
   appears in paperless-gpt → accept → tag present in paperless-ngx.

## Risks / accepted trade-offs

- CPU-only inference: qwen2.5:3b suggestions are slow (seconds-to-tens of
  seconds per document) — acceptable for a single-user dev setup with
  `SUGGESTION_WORKERS=1`.
- NodePort 32081 is reachable from the codespace port-forward only (not the
  public internet), but paperless-gpt has no auth of its own — the Traefik
  path is gated by basicAuth, the NodePort path relies on codespace
  network isolation.
- Traefik sub-path (`/paperless-gpt`) redirect/asset breakage is known; the
  NodePort path is the primary clean path. Traefik path kept as secondary
  for browser convenience when it works.
- Cluster recreate required for the k3d-dev port mapping — all existing dev
  state re-syncs from Git; paperless dev data on its PVC survives (k3d
  volume) but in-flight docs may need re-processing.
- In-repo chart for paperless-gpt is intentionally minimal — maintenance
  burden accepted for the appset's Helm-only requirement.
- Community otwld chart, not official — mitigated by pinning the chart
  version and values schema.

## Out of scope (follow-ups)

- RAG / embeddings over paperless documents (needs an embedding model and
  a vector store).
- OCR vision model (e.g. qwen2.5-vl) for scanned-document assist.
- Prod deployment of either app.
- Persistent model storage beyond the dev 5Gi PVC; model version pinning
  automation.
- Postgres for paperless-gpt (SQLite/emptyDir is loseable-by-design in dev).
